# 轻传架构（1.1.0）

SwiftUI 为 Mac/iPhone 提供统一业务界面。BridgeDropCore 包含 Codable 模型、认证加密、磁盘接收账本及局域网/中继网络接口。两种网络模式使用同一审批和传输协议。

## 身份与配对

本机 UUID 是路由标识，Bonjour 名称只是发现线索。2026-10-17 起，新二维码为 `org.local.bridgedrop://pair?v=1&payload=<Base64URL(JSON)>` 应用链接，使用 URLComponents / queryItems 构造和解析。内层邀请码仍是原有 `bridgedrop-invite-v1` JSON，32 字节秘密的生成、Keychain 存储与传输协议不变；有效期内的旧原始 JSON 仍可在新应用内扫码或粘贴导入。二维码没有上传生成网站。

`PairingInviteCodec` 统一解析应用链接和旧 JSON；严格拒绝错误 scheme / host / path、URL 用户信息/端口/fragment、未知/缺失/重复参数、错误版本、超长或非规范 Base64URL 与畸形 JSON，再调用原有 `PairingVault.validate`。JSON 上限仍为 8192 字节，链接入口上限 12 KiB。无效输入清除之前的可确认预览，错误文字不包含邀请内容。

iOS 的 CFBundleURLTypes 注册 `org.local.bridgedrop`，SwiftUI onOpenURL 与内置扫描器、粘贴入口统一调用 review-only 方法，切到导入页并显示设备名、ID、连接地址和有效期。收到链接只预填，不调用 importInvite、不写 Keychain、不信任设备。用户明确勾选信任并点击确认后，importInvite 再次校验（包括是否在预览后到期），才保存并连接。已有连接不因一个预览被替换为新配对。

为避免冷启动或重新激活时 `.task` / scenePhase 早于 onOpenURL 自动连接，iOS 启动只读取现有配置；新的本机密钥仅暂存内存，明确启用连接或确认导入时才持久化。进入后台仍暂停，返回后由用户点击“开启 / 恢复已有配对连接”。Mac 的正常启动保持原有自动接收行为。测试通过注入隔离存储验证 review 路径不产生配对写入或连接。

应用链接不是 HTTP 页面，47185 仍是加密 TCP 端口。不增加浏览器传输页、假域名或 apple-app-site-association。自定义 scheme 不能保证全球唯一归属，也不保证系统相机一定显示打开入口；正式分发并拥有域名后再评估 Universal Links。当前没有签名的 iPhone 真机验证。

邀请码仍没有独立来源签名。编码损坏或违反原校验的修改会被拒绝，但把密钥等字段换成另一组合法值不能仅靠 Base64URL/JSON 校验鉴别；设备来源仍需用户核对，实际连接另经原有共享密钥认证。不要将格式校验称为对任意篡改的密码学检测。

v1 采用共享密钥，不使用公钥逐设备身份，也没有前向保密或单次邀请服务器登记。已导入密钥的设备具有配对组权限，解除配对需更换组密钥并重新配对。邀请码时效仅限制首次导入，不使已保存的密钥自动到期。

## 消息加密

CryptoKit AES-GCM 随机 nonce；通过 HKDF-SHA256 将共享秘密派生为与协议及配对组绑定的密钥。协议标识、pairID、senderID、receiverID、requestID 作为认证元数据，方向通过发送方和接收方标识绑定；操作内容、文件名、哈希和数据块均在密文中。响应的身份字段必须匹配原请求。收到无效密文不执行文件操作。

应用协议通过 UUID 传输身份、持久状态、连续偏移与重复块字节比对保证幂等。它不是一个带时间窗的通用网络防重放协议；配对密钥持有人可执行组内操作，收到内容仍需用户审批。

## 局域网

NWListener / NWBrowser 广告并浏览 `_bridgedrop._tcp`，默认端口 47185，参数启用系统可选 peer-to-peer 能力。TCP 消息用 4 字节大端长度前缀，消息最大 2 MiB。读循环处理拆包；连接超时和任务取消会清理连接。每个交换独立建立连接，简单可靠，吞吐量仍需实测并可后续优化为复用连接。

没有相同 Apple 账户要求，也不调用 AirDrop。手动地址不能绕过路由器隔离。Network.framework 原始 TCP 本身不加密，实际内容保密来自上面的 AES-GCM。

## 中继

HTTPS URLSession 客户端 + 私有 Python/SQLite 参考服务。Bearer 服务凭据与配对加密密钥分开；服务器从不接收解密密钥。最长 25 秒长轮询，GET 队列不删除数据，响应持久化后才确认消息。相同请求 ID 重试复用原始密文，防止随机 nonce 改变被视为冲突。

请求及响应保留窗口 24 小时，密文逻辑配额 256 MiB，请求上限 2 MiB。消息确认后释放原消息密文，保留指纹和响应，以容纳多分块文件。SQLite 物理文件可能大于逻辑配额。单共享服务器凭据适合个人自用，不是多租户隔离设计。公网 HTTPS 入口尚未部署。

## 状态与保存

Offer → awaitingApproval → receiving → completed。拒绝、取消和校验失败进入相应终态，需要重新发送的新传输 ID。成功后的取消不删除已保存文件。

分块写盘同步后提交 ledger 才 ACK 偏移；完成先校验、rename 并同步目录，再提交完成 ledger 才 ACK 完成。恢复处理多写尾部、短文件、rename 后账本尚未提交等窗口。读取 ledger 时重建路径，不信任存储的路径字符串，拒绝路径穿越与符号链接。

源文件通过 security scope 与 NSFileCoordinator 协调复制到本机 Outbox，发送任务状态原子保存。UI 暂停时保留取消任务登记直到旧任务退出，避免快速继续启动同一传输的第二个任务。界面没有自动监视剪贴板。

## 平台边界

iPhone 第一版主动在进入后台时停止网络服务。iOS 26 的长任务 API 可作为后续增强，未在本版实现；也未实现后台 URLSession 调度或 APNs。2026-10-29 使用完整 Xcode 和 iOS SDK 已编译模拟器及设备架构，独立模拟器已安装、启动并接受测试应用链接；iPhone 确认页目视、系统相机及实际双设备传输仍待验收。

## 1.1.0 发送恢复与资源限制

`TransferSender` 是独立的发送状态机。短暂连接故障最多自动恢复四次，退避带抖动；恢复时重新提交相同 manifest 和传输 ID，获取接收端持久化断点后继续。每次完成确认必须同时匹配 completed 与总长度，分块确认必须恰好匹配本块末尾。拒收、取消、无效确认、凭据或证书错误不自动恢复。原有单请求三次重试仍复用原密文，整个等待审批使用单调时钟十分钟期限。

应用最多同时运行两个发送器，其余排队；文件暂存按顺序执行。排队任务取消后不会再发出 offer。NWPathMonitor 在可用网络变化时刷新邀请地址和已认证发现，并重新探测配置的地址。活动传输持有暂时的防休眠令牌，iPhone 只在前台活动传输时关闭自动锁屏，暂停或完成后释放；不扩大后台运行承诺。Mac 同 bundle ID 的第二实例会激活已有实例并退出。
