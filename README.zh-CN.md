# 轻传 BridgeDrop

<img src="assets/app-icon.png" alt="轻传图标" width="96">

[English](README.md) | 简体中文

在 Mac 与 iPhone 之间发送文件和粘贴文本的原生应用，通过应用内配对连接，不要求相同 Apple 账户，也不依赖隔空投送或 iCloud。界面默认英文，可在 Settings → Language 选择简体中文；选择会保留。

## 安装与使用

- [下载 Mac 1.3.0](../../releases/tag/v1.3.0)：Apple 芯片、macOS 13 或更新版本。解压后将“轻传.app”放入应用程序目录。运行下载版不需要开发工具。macOS 可能提示安全检查，请按系统及 [Apple 官方指引](https://support.apple.com/102445)处理。
- iPhone 目前提供源码和 Xcode 工程，需使用自己的 Team 构建安装，尚无 App Store、TestFlight 或可直接安装的 IPA。见[安装说明](docs/INSTALL.md)。

两端打开轻传，在 Mac 显示配对邀请。iPhone 系统相机若提供轻传链接入口即可点击；否则用轻传内“导入邀请码 → 扫描另一台设备”，或文本导入。核对设备信息后明确确认，才会保存配对并连接。新二维码使用应用链接，旧 JSON 邀请仍能在应用内导入。邀请码含连接凭据，只应交给轻传处理，不应进入搜索框或在线解析网站。

选择对方，发送文件或主动粘贴的文字；接收方默认逐项确认，也可开启自动接收当前配对组的新请求。收到文字后手动点击复制，不会自动覆盖剪贴板。iPhone 回到前台时可点击“开启 / 恢复已有配对连接”，传输期间请保持两端打开。

发送成功后，如输入框未被修改会自动清空。发送和接收区域支持删除单条记录或批量清除已结束记录；已接收文件和恢复凭据会保留。

## 本次稳定性改进

- 短暂断网后有限自动重试，使用同一传输 ID 查询持久断点；接收端重启或确认消息丢失不会重复生成接收文件。
- 最多两个任务同时发送，文件准备按顺序执行；排队任务可以取消，快速点击继续不会启动重复发送器。
- 每块 256 KiB，接收端写盘及账本保存后才确认；最终 SHA-256 和保存完成后才能显示“已送达”。发送端校验准确偏移与总长度。
- 网络变化后重新发现并尝试已配置地址；Mac 重复打开时优先激活已有实例。
- 活动传输期间防止自动休眠；iPhone 手动锁屏、切换应用和系统暂停仍可能中断，重新打开后可继续。
- 文本保留 UTF-8 内容、换行、空白和表情；无自动剪贴板监视。

文件上限 10 GiB，文字上限 1 MiB，每次最多选择 20 个文件；文件夹请先压缩。这些协议上限不代表已完成同等大小的真机性能测试。

## 网络与保存

优先同一可互访局域网，Bonjour 不可用时可手动填写另一台设备的 IP。手动地址不能绕过访客网络隔离，47185 端口提供加密 TCP 而不是网页。跨网络需要自行部署 [HTTPS 中继](relay/README.md)，本项目没有预置公共中继。

配对秘密保存在钥匙串，传输内容使用 AES-GCM。当前采用共享配对密钥，移除配对后两端需要重新配对。接收内容、暂存文件和记录留在本机，应用不另外加密这些本地文件；重要内容请独立备份。[架构与安全边界](docs/ARCHITECTURE.md)。

## 验证与开发

本地 Mac 和 iPhone 已验证双向文字、约 5 KB 和 2 MiB 文件、自动接收及手动确认。自动化检查覆盖断点恢复、配对、记录管理和输入保护；详细范围见[验证记录](docs/VALIDATION.md)。

**iOS 26.2 系统相机、公网中继、大文件及更多真实网络条件仍待验收。**见[验证记录](docs/VALIDATION.md)、[成熟项目调研与采用决策](docs/RESEARCH.md)和[构建说明](docs/BUILDING.md)。
